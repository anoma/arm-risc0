# Compliance Circuit

This crate contains the RISC Zero compliance circuit and its benchmarks.
Succinct STARK proofs are generated by default.

## Benchmark Cases

Four benchmark groups cover the two axes that drive proving cost: kind-point
resolution (table lookup vs. `hash_to_curve`) and conversion witness count/table
size.

| Case | Swept parameter | Description |
|------|-----------------|-------------|
| `empty_table` | batch size | No precomputed kind table; circuit calls `hash_to_curve` for every resource |
| `lookup_table` | batch size | Kind points loaded from `kind_table.json`; circuit resolves them via table lookup |
| `conversion_count` | # conversion witnesses | 1 balanced resource pair (lookup-table path); sweeps 0–8 conversion witnesses; conversion table has exactly as many entries as conversions |
| `conversion_table_size` | # table rows | 1 balanced resource pair + 1 conversion witness (lookup-table path); sweeps table size 1–64; dummy entries prepended for worst-case linear scan |

The trailing number in each benchmark name is the value of the swept parameter.

## Running

CPU:

```bash
cargo bench --features prove --bench compliance
```

CUDA:

```bash
cargo bench --features prove,cuda --bench compliance
```

Skip proof generation (validates witness assembly only):

```bash
RISC0_DEV_MODE=1 cargo bench --features prove -p compliance
```

## Results

All times are criterion medians on GPU NVIDIA 5090 .

### Batch size scaling

Without conversion constraints:

| batch | `empty_table` | `lookup_table` |
|------:|:-------------:|:--------------:|
|     1 |    2.477 s    |    809.3 ms    |
|     2 |    3.842 s    |    897.3 ms    |
|     4 |    7.006 s    |     1.458 s    |
|     8 |   13.615 s    |     1.582 s    |

With conversion constraints enabled (0 conversions, empty conversion table):

| batch | `empty_table` | `lookup_table` |
|------:|:-------------:|:--------------:|
|     1 |    2.594 s    |    938.3 ms    |
|     2 |    3.676 s    |    904.4 ms    |
|     4 |    6.929 s    |     1.389 s    |
|     8 |   12.126 s    |     1.507 s    |

`lookup_table` amortizes the `hash_to_curve` cost so proving time stays nearly
flat up to 8 resources. `empty_table` scales roughly linearly because each
resource requires a fresh curve hash.

### Conversion count (1 resource pair, lookup-table path)

| conversions | time |
|------------:|-----:|
|           0 | 924 ms |
|           1 | 1.038 s |
|           2 | 1.367 s |
|           4 | 1.668 s |
|           8 | 2.854 s |

The 0-conversion baseline matches `lookup_table/1`. Each additional conversion
witness adds roughly 200–350 ms; cost scales approximately linearly.

### Conversion table size (1 resource pair + 1 conversion, lookup-table path)

| table rows | time |
|-----------:|-----:|
|          1 | 913 ms |
|          4 | 1.314 s |
|         16 | 1.358 s |
|         64 | 2.996 s |

Cost is flat between 4 and 16 rows. The jump at 64 rows reflects the conversion
table scan crossing a memory threshold.
